# ISA Subset

This document tracks the RV32I subset implemented by the project and the level
of evidence behind each group. Two cores live in the tree:

- the **single-cycle core** (`rtl/single_cycle/`), frozen at v0.4.0 with a
  constrained-random regression — the only part of the project currently
  claimed as *verified*;
- the **five-stage pipeline** (`rtl/pipeline/`), in progress at v0.5.0 with
  directed bring-up only — implemented, *not* verified.

## v0.3.0 Verified Single-Cycle Subset

The v0.3.0 release verifies the supported single-cycle RV32I base integer
datapath with VCS and the SystemVerilog core testbench.

| Group | Instructions | Verification level |
|---|---|---|
| R arithmetic | `add`, `sub` | Complete single-cycle directed regression |
| R logical | `and`, `or`, `xor` | Complete single-cycle directed regression |
| R compare | `slt`, `sltu` | Complete single-cycle directed regression |
| R shift | `sll`, `srl`, `sra` | Complete single-cycle directed regression |
| I arithmetic/logical | `addi`, `xori`, `ori`, `andi` | Complete single-cycle directed regression |
| I compare | `slti`, `sltiu` | Complete single-cycle directed regression |
| I shift | `slli`, `srli`, `srai` | Complete single-cycle directed regression |
| Loads | `lb`, `lh`, `lw`, `lbu`, `lhu` | Complete single-cycle directed regression |
| Stores | `sb`, `sh`, `sw` | Complete single-cycle directed regression |
| Branches | `beq`, `bne`, `blt`, `bge`, `bltu`, `bgeu` | Complete single-cycle directed regression |
| Jumps | `jal`, `jalr` | Complete single-cycle directed regression |
| Upper immediates | `lui`, `auipc` | Complete single-cycle directed regression |
| Register zero | `x0` write ignored, read returns zero | Complete single-cycle directed regression |

The verification level above means that the instruction is exercised through
the complete single-cycle core, including instruction fetch, decode, register
read, immediate generation, execution, memory or PC side effects where
applicable, writeback, and final signature checking.

## Expected Files

Expected files use two record types:

```text
TXN W <addr_hex> <data_hex> <wstrb_bin>
TXN R <addr_hex> <data_hex> <wstrb_bin>
SIG <addr_hex> <data_hex>
```

- `TXN` records check observed memory transactions.
- `SIG` records check final architectural signatures in data memory.

The files are generated by:

```sh
./tools/rv32i_ref.py --all
```

## Five-Stage Pipeline Subset (v0.5.0, in progress)

The pipeline reuses the same decoder, ALU, immediate generator, register file
and load/store unit, so the instruction list it *implements* is the same as the
single-cycle core's. What differs is the evidence level: the pipeline has
directed bring-up runs only, no oracle-driven regression yet.

| Group | Instructions | Pipeline evidence today |
|---|---|---|
| R arithmetic / logical / compare / shift | `add`, `sub`, `and`, `or`, `xor`, `slt`, `sltu`, `sll`, `srl`, `sra` | `alu_rtype_test` runs the full program; 10/10 observed memory transactions match the single-cycle expected file |
| I arithmetic / logical / compare / shift | `addi`, `slti`, `sltiu`, `xori`, `ori`, `andi`, `slli`, `srli`, `srai` | `alu_itype_test`; 12/12 transactions match |
| Loads / stores | `lb`, `lh`, `lw`, `lbu`, `lhu`, `sb`, `sh`, `sw` | `load_store_width_test`; 13/13 transactions match, including byte/halfword strobes and signed/unsigned extension |
| Branches | `beq`, `bne`, `blt`, `bge`, `bltu`, `bgeu` | `branch_matrix_test`; 66 of 96 static instructions retire (taken/not-taken paths) and 12/12 transactions match |
| Jumps / upper immediate | `jal`, `jalr`, `lui`, `auipc` | `jump_u_type_test`; 10 of 15 static instructions retire and 3/3 transactions match |
| Register zero | `x0` write ignored, read returns zero | `x0_test`; 8/8 transactions match |
| Trap | `ebreak` → `EXC_BREAKPOINT` at WB, flush + sticky `halted` | exercised by every bring-up run (the programs end with `ebreak`); the testbench checks exactly one `EXC_BREAKPOINT` trap and no timeout |
| Trap | `ecall` → `EXC_ECALL_MMODE`, illegal encoding → `EXC_ILLEGAL_INSTR`, misaligned load/store | implemented in RTL (ID decode / MEM misalignment), **not** exercised by any program in `programs/asm/` |
| Hazard behaviour | load-use stall, EX/MEM + MEM/WB forwarding, WB→ID bypass, redirect flush, memory freeze | exercised incidentally by the same six programs (see `04_hazard_forwarding.md` §9 for what is *not* deliberately tested) |

Wording used above, in the project's usual sense:

- *implemented* — the RTL exists and elaborates;
- *bring-up exercised* — a directed program ran on the pipeline and produced a
  plausible trace (transaction stream matching the single-cycle reference);
- *verified* — nothing about the pipeline is verified yet.

Testbench details and the full evidence tables are in
[11_v0_5_0_pipeline_bringup.md](11_v0_5_0_pipeline_bringup.md).

## Out Of Scope For v0.3.0

The following behavior is intentionally not claimed by this release:

- `fence`
- `ecall`
- `ebreak`
- CSRs and privileged ISA behavior
- traps, interrupts, and exception return
- misaligned-access trap handling
- real bus protocols or wait states
- five-stage pipeline behavior

These are future architecture decisions, not failures of the v0.3.0
single-cycle milestone.
